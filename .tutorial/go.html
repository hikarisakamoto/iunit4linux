Before you start

1The packet builder

Turn two temperatures into the twelve-byte packet. No I/O, so it is fully testable.

1. Encode one available reading

Start packet.go with a Reading type containing Celsius float64 and Valid bool, then implement func digits(r Reading) [3]byte. For now, handle available values in the range 0–99.9. Use your own names if you prefer; keep them consistent in the tests and callers.

Work in whole tenths: 44.3 → 443. Given v := 443, calculate v / 100, v / 10 % 10, and v % 10. Repeat with v := 70. Which expression removes the tens digit from the ones place?

Round to the nearest tenth, with halfway values rounded up after clamping. This is a display choice, not a checksum or HID requirement. For 44.31, rounding gives 44.3; math.Ceil(c * 10) gives 44.4. Add a test for that difference if your current implementation uses Ceil.

packet_test.go — first test 
package main

import "testing"

func TestDigits(t *testing.T) {
	got := digits(Reading{Celsius: 44.3, Valid: true})
	want := [3]byte{4, 4, 3}
	if got != want {
		t.Errorf("got %v, want %v", got, want)
	}
}

Run go test -run '^TestDigits$' -v. Before extending the test, change its expected last digit to 2 and run it again. Check that the failure names the differing arrays, then restore 3.

2. Define the boundary behavior

Reading{} means unavailable; Reading{Celsius: 0, Valid: true} means a measured zero. Check Valid first and return [3]byte{0xEE, 0xEE, 0xEE} when it is false. Then clamp available values to 0–99.9 before rounding. Assume finite values: later reads parse integer millidegrees.

Extend the test with zero, negative, above-range, and absent readings. Arrays of the same type can be compared with ==; a []byte slice cannot. A table test is a slice of cases with an input and an expected result, followed by the same assertion for each case.

3. Assemble the packet

Implement func buildPacket(cpu, gpu Reading) [12]byte. Fill the fixed bytes, place the CPU and GPU triples, then compute byte 11 from bytes 0–10. Keep the report-ID prefix out of this function; it belongs to the writer in step 5.

Reach for

p[5:8] is a slice covering indexes 5, 6, and 7: the upper bound is excluded. c[:] views all three elements of the array c. copy(p[5:8], c[:]) copies those values into the packet. Changing the slice's elements changes the underlying array.

Gotcha · you cannot slice a returned array

copy(p[5:8], digits(cpu)[:]) does not compile: cannot slice unaddressable value digits(cpu) (value of type [3]byte). That returned array is not addressable, and slicing an array requires an addressable value. Assign it to a variable first.

The checksum

A running byte sum wraps modulo 256 in Go, which does implement this checksum. A uint32 sum followed by byte(sum) makes the two stages explicit: add, then keep the low eight bits. For the first vector, the full sum is 280 = 0x118, so byte 11 is 0x18.

Hint — digit arithmetic and packet offsets

After clamping, int(c * 10 + 0.5) rounds a non-negative value into whole tenths. Integer division discards the remainder; % 10 keeps the last digit. For 70, the result is [0, 7, 0].

Use the protocol's byte-offset table to place the triples. A digit 4 is 0x04, not the character '4' (0x34). Check those offsets before debugging the checksum.

Checkpoint

Table-test the two vectors from the protocol page:

expected 
44.3 / 42.0   ->  55 AA 01 01 06 04 04 03 04 02 00 18
blank / blank ->  55 AA 01 01 06 EE EE EE EE EE EE 9B

Add edge cases: 0.0 gives 00 00 00, 99.9 gives 09 09 09, 150.0 clamps to 09 09 09, and -5.0 clamps to 00 00 00. Test one absent half at a time too, to catch swapped CPU/GPU offsets. A checksum-only assertion would miss swapped fields; compare complete packets against independently specified bytes.

Reference implementation — step 1
packet.go 
package main

// The zero value represents an unavailable reading.
type Reading struct {
	Celsius float64
	Valid   bool
}

var blank = [3]byte{0xEE, 0xEE, 0xEE}

// digits splits a reading into tens, ones and tenths.
func digits(r Reading) [3]byte {
	if !r.Valid {
		return blank
	}
	c := r.Celsius
	if c < 0 {
		c = 0
	}
	if c > 99.9 {
		c = 99.9
	}
	v := int(c*10 + 0.5) // round, then work in tenths
	return [3]byte{byte(v / 100), byte(v / 10 % 10), byte(v % 10)}
}

func buildPacket(cpu, gpu Reading) [12]byte {
	var p [12]byte
	p[0], p[1] = 0x55, 0xAA
	p[2], p[3], p[4] = 0x01, 0x01, 0x06

	// Assign first: digits(cpu)[:] would not compile.
	c, g := digits(cpu), digits(gpu)
	copy(p[5:8], c[:])
	copy(p[8:11], g[:])

	var sum uint32
	for _, b := range p[:11] {
		sum += uint32(b)
	}
	p[11] = byte(sum)
	return p
}

package main

import "testing"

func TestBuildPacket(t *testing.T) {
	cases := []struct {
		name     string
		cpu, gpu Reading
		want     [12]byte
	}{
		{"vector", Reading{44.3, true}, Reading{42.0, true},
			[12]byte{0x55, 0xAA, 0x01, 0x01, 0x06, 4, 4, 3, 4, 2, 0, 0x18}},
		{"blank", Reading{}, Reading{},
			[12]byte{0x55, 0xAA, 0x01, 0x01, 0x06,
				0xEE, 0xEE, 0xEE, 0xEE, 0xEE, 0xEE, 0x9B}},
		{"cpu only", Reading{44.3, true}, Reading{},
			[12]byte{0x55, 0xAA, 0x01, 0x01, 0x06,
				4, 4, 3, 0xEE, 0xEE, 0xEE, 0xDC}},
		{"gpu only", Reading{}, Reading{42.0, true},
			[12]byte{0x55, 0xAA, 0x01, 0x01, 0x06,
				0xEE, 0xEE, 0xEE, 4, 2, 0, 0xD7}},
	}
	for _, tc := range cases {
		got := buildPacket(tc.cpu, tc.gpu)
		if got != tc.want {
			t.Errorf("%s:\n got %X\nwant %X", tc.name, got, tc.want)

	}

2Read one temperature

Read one sensor file and return Celsius. Use a known path first; discovery comes next.

1. Trace the conversions

The file contains "47125\n", not a floating-point number. Write down the value and Go type after each operation:

data trace 
ReadFile       []byte   [52 55 49 50 53 10]
string + trim  string   "47125"
Atoi           int      47125
divide         float64  47.125
digits         [3]byte  [4 7 1]

Keep reading and display rounding separate. readTemp should return 47.125, not 47.1; the packet builder decides what fits on the panel.

2. Implement the reader

In sensors.go, write readSysfs(path string) (string, error) to read and trim, then readTemp(path string) (float64, error) to parse and convert units. Check each error before using the returned value. On failure, return zero and the error; zero alone cannot distinguish failure from a measured 0 °C.

Wrap parsing errors with the path and %w. That adds context while preserving the original error for checks such as errors.Is. Do not log in the reader; the caller decides whether to exit or continue.

3. Run one read

Add main.go that accepts one path, calls readTemp, and prints both the Celsius value and its digit triple. On error, print the error and exit nonzero. Use go run . /path/to/temp1_input; choose a current path from the foundations warm-up.

Reach for

os.ReadFile — not os.Open and a Scanner; these files are a handful of bytes. strings.TrimSpace, strconv.Atoi, and fmt.Errorf with %w to wrap.

Gotcha · include the path in every error

os.ReadFile returns a *PathError, so its message names the file. strconv.Atoi's does not — you get strconv.Atoi: parsing "47125\n": invalid syntax, which does not say which file. Wrap the parse error with the path: fmt.Errorf("parse %s: %w", path, err).

Gotcha · the trailing newline

Forget TrimSpace and Atoi fails with invalid syntax: the \n is there in the quoted value, but easy to miss.

Gotcha · integer division eats the decimal

If milli is an int, milli / 1000 is integer division. Compare float64(milli / 1000) with float64(milli) / 1000: converting after division cannot restore the fraction.

Hint — keep the error path separate

Use b, err := os.ReadFile(path), handle err != nil, and only then convert b to a string. Repeat that pattern around strconv.Atoi. A successful return ends with nil as its error value.

Checkpoint

First check a stable input with an ordinary file, then read the real sensor:

shell — no hardware needed for the first read 
printf '47125\n' > /tmp/antec-temp-input
go run . /tmp/antec-temp-input
# 47.125 °C; panel digits [4 7 1]
go run . /sys/class/hwmon/hwmon6/temp1_input

Replace hwmon6 with your current CPU sensor directory. Compare the live result with sensors; readings taken at different times may differ.

Then break it on purpose twice: point it at a path that does not exist, and at .../name, which exists but will not parse. Both should produce one clean line naming the file, not a panic or a bare invalid syntax. Temporarily remove TrimSpace and retry the stable input. Explain why a file that looked numeric stopped parsing, then restore the trim.

Reference implementation — step 2
sensors.go 
package main

import (
	"fmt"
	"os"
	"strconv"
	"strings"
)

// readSysfs reads a small sysfs file and trims the trailing newline.
// Every read in this program goes through here so the trim can't be forgotten.
func readSysfs(path string) (string, error) {
	b, err := os.ReadFile(path)
	if err != nil {
		return "", err // *PathError already names the file
	}
	return strings.TrimSpace(string(b)), nil
}

// readTemp returns degrees Celsius from a hwmon tempN_input file.
func readTemp(path string) (float64, error) {
	s, err := readSysfs(path)
	if err != nil {
		return 0, fmt.Errorf("read temperature: %w", err)
	}
	milli, err := strconv.Atoi(s)
	if err != nil {
		return 0, fmt.Errorf("parse %s: %w", path, err)
	}
	return float64(milli) / 1000, nil
}

3Find the sensors

List the input paths and labels belonging to each CPU/GPU driver. Gather candidates here; choose among them in step 4.

hwmon6 is an enumeration number, not a sensor identity. It can change after a reboot. A path saved from a previous boot may exist but belong to a different driver.

1. Discover directories by identity

Write hwmonByDriver(driver string) []string. Enumerate /sys/class/hwmon/hwmon*, read each name with your step-2 helper, and keep matches. Skip entries whose name cannot be read; they might disappear during a scan. An empty slice means no candidates, not a temperature of zero.

2. Describe the inputs

Define sensor with path and label string fields. Write tempInputs(dir string) []sensor: enumerate temp*_input, derive each _label path, and append a sensor. Keep an input even when its label is missing.

For temp3_input, predict the label path before coding the string operation. Return paths rather than temperatures so discovery does not have to repeat every second.

3. Inspect before selecting

Replace the one-path main.go with an inventory printer for k10temp, coretemp, and amdgpu. Print each matching directory and every input/label pair. Do not choose the first GPU yet.

Reach for

filepath.Glob handles both enumerations and saves you a manual ReadDir-and-filter. filepath.Join to build paths. strings.TrimSuffix to turn temp1_input into temp1_label. strings.EqualFold so label matching is not case-sensitive.

Gotcha · do not filter on IsDir

Entries under /sys/class/hwmon are symlinks (foundations, section 07), and DirEntry.IsDir() reports the type of the link, so filtering on it returns nothing. filepath.Glob sidesteps this. With ReadDir, either os.Stat the path (which follows links) or try to read name and skip entries where that fails.

Gotcha · numbering has holes, and sorts wrong

The example k10temp directory has no temp2. A loop over numbers 1 through the input count would try a missing file and overlook temp4.

And filepath.Glob returns results sorted lexically: hwmon10 sorts before hwmon2, so first in the list does not mean first device or best sensor.

Gotcha · labels are optional

A missing _label is normal (spd5118, ath12k_hwmon): treat the read failure as an empty string, or a RAM sensor you do not care about aborts the whole scan.

Hint — accumulate a list

Start with var out []sensor, or make([]sensor, 0, len(matches)). The latter reserves capacity but has length zero. Add each entry with out = append(out, sensor{path: p, label: label}); append returns the updated slice.

strings.TrimSuffix(p, "_input") + "_label" transforms the path without assuming which input number it contains.

Checkpoint

Compare the listed driver directories with the shell:

shell 
for d in /sys/class/hwmon/hwmon*; do echo "$d $(cat $d/name)"; done

For one directory, compare the printed input paths with ls /sys/class/hwmon/hwmonN/temp*_input. Substitute the number you just found. On the example machine, k10temp has inputs 1, 3, and 4. Your list must reflect the files actually present, including inputs without labels.

Reference implementation — step 3
sensors.go — add declarations and merge filepath into imports 
import (
	"path/filepath"
)

type sensor struct {
	path  string // .../tempN_input
	label string // "Tctl", "edge", … or "" when the device exposes none
}

// tempInputs lists every temperature sensor in one hwmon directory.
func tempInputs(dir string) []sensor {
	// Glob, not ReadDir: entries under /sys/class/hwmon are symlinks and
	// DirEntry.IsDir() reports false for all of them.
	matches, err := filepath.Glob(filepath.Join(dir, "temp*_input"))
	if err != nil {
		return nil
	}
	out := make([]sensor, 0, len(matches))
	for _, p := range matches {
		// A missing label file is normal, not an error.
		label, _ := readSysfs(strings.TrimSuffix(p, "_input") + "_label")
		out = append(out, sensor{path: p, label: label})
	}
	return out
}

// hwmonByDriver returns every hwmon directory belonging to a driver.
func hwmonByDriver(driver string) []string {
	dirs, _ := filepath.Glob("/sys/class/hwmon/hwmon*")
	var out []string
	for _, d := range dirs {
		if name, err := readSysfs(filepath.Join(d, "name")); err == nil && name == driver {
			out = append(out, d)
		}
	}
	return out
}

4Pick the right GPU

Given two amdgpu instances, choose the discrete card and not the integrated one.

Among candidates for a driver, take the one with the most temperature inputs (the two-amdgpu problem, foundations, section 08), and log.Printf the paths you chose at startup; the heuristic can be wrong on another machine. Fold this into the sensor finder from step 3; the rule is harmless for k10temp, which has one instance.

Implement two decisions, in order

  1. Write findSensor(driver string, preferred ...string) (string, bool). First choose the driver instance with the largest input list. With a strict > comparison, a tie keeps the first candidate encountered.
  2. Within that instance, search for preferred labels in the caller's order. preferred ...string accepts zero or more strings; inside the function it is a []string. Return the first matched path.
  3. If there are inputs but no matching label, return the first input. If there are no inputs, return "", false. Add findCPU and findGPU wrappers for the driver/label preferences.

Trace these candidates before running the finder:

selection exercise — fictional paths 
amdgpu A: /A/temp1_input edge
amdgpu B: /B/temp1_input junction
          /B/temp2_input edge
          /B/temp3_input mem

preferred "edge"              → which path?
preferred "missing", "mem"    → which path?
preferred "missing"           → which fallback?
Hint — preference order determines loop order

Choose B before checking labels. Put the preferred-label loop outside the sensor loop; otherwise file order can override the caller's preference. The answers are /B/temp2_input, /B/temp3_input, and /B/temp1_input.

Checkpoint

Replace the inventory main with a printer for the selected CPU/GPU paths and readings. Run go run .. On an AMD machine, the CPU choice should belong to k10temp and prefer Tctl; the GPU choice should belong to the amdgpu instance with the most inputs and prefer edge. Confirm against the inventory, labels, and sensors, rather than an old hwmon number.

Call findSensor("nonexistent-driver") temporarily. It should report no selection without indexing an empty slice. If two real GPUs have equal input counts, this heuristic cannot identify the one you want; a later path override can make that choice explicit.

Reference implementation — step 4
sensors.go — add 
// findSensor picks a temperature input for a driver, preferring the first
// label in preferred that exists. Among several instances of the same driver
// (a discrete GPU and an iGPU both bind amdgpu) the one exposing the most
// sensors wins — a discrete card reports edge+junction+mem, an iGPU only edge.
func findSensor(driver string, preferred ...string) (string, bool) {
	var best []sensor
	for _, dir := range hwmonByDriver(driver) {
		if s := tempInputs(dir); len(s) > len(best) {
			best = s
		}
	}
	if len(best) == 0 {
		return "", false
	}
	for _, want := range preferred {
		for _, s := range best {
			if strings.EqualFold(s.label, want) {
				return s.path, true
			}
		}
	}
	return best[0].path, true
}

// findCPU and findGPU encode the per-vendor preferences in one place.
func findCPU() (string, bool) {
	if p, ok := findSensor("k10temp", "Tctl"); ok {
		return p, true
	}
	return findSensor("coretemp", "Package id 0")
}

func findGPU() (string, bool) {
	return findSensor("amdgpu", "edge")
}

5Find the device and write to it

Locate your /dev/hidrawN by USB ID, then put a number on the panel from your own code.

Discovery is the same directory-scanning shape as step 3 with a different matcher: walk /sys/class/hidraw/*, read each device/uevent, and look for the HID_ID line.

Build and check the report before discovery

  1. Implement send(f *os.File, p [12]byte) error. A zero-initialized [13]byte supplies the report-ID prefix; copy the packet into indexes 1–12. Call Write once, check its error, then check the byte count.
  2. Replace main.go with a one-shot sender for the 44.3/42.0 vector. Add --out with the standard flag package. In file mode, create or truncate the output file so a previous run cannot leave trailing bytes.
  3. After the file check passes, implement findHidraw() (string, bool). With no --out, discover and open the device, then send the same packet.
Gotcha · eight hex digits, not four

HID_ID=0003:00002022:00000522: the vendor and product fields are zero-padded to eight digits (foundations, section 10). Build the needle with fmt.Sprintf(":%08X:%08X", vid, pid); the kernel writes uppercase hex too, and the reference upper-cases both sides anyway.

The write half enforces the two rules from the foundations page: a 13-byte buffer (0x00, then the packet), sent in a single Write.

Reach for

os.OpenFile(path, os.O_WRONLY, 0). Not os.Create: it adds O_CREAT|O_TRUNC and opens read-write. If a device path is absent and permissions allow it, Create can make an ordinary file there. Reserve it for the explicit scratch-file branch. The device needs only O_WRONLY; this program never reads its input endpoint.

Reaching for the wrong tool

bufio.NewWriter around the device, or writing the header and body in two calls: hidraw maps one write() syscall to one report (foundations, rule two). Use an unbuffered *os.File.Write and confirm the syscall with strace. Treat a short write as a failed report; sending the remaining bytes in another call would be a second report, not a repair.

Hint — keep the two open policies distinct

Parse out := flag.String("out", "", "write one report to a scratch file") before opening anything. *out != "" selects os.Create(*out). Otherwise, discover the node and use os.OpenFile. Both branches can share the same send call.

Checkpoint

Build the one-shot sender and write a scratch file first; no root needed:

shell 
$ go build -o antec-display .
$ ./antec-display --out /tmp/panel.bin
$ wc -c /tmp/panel.bin
13 /tmp/panel.bin
$ hexdump -C /tmp/panel.bin
00000000  00 55 aa 01 01 06 04 04  03 04 02 00 18

Run the file command twice. Its size must stay 13, and the twelve bytes after the prefix must match step 1. A file validates content and length; it does not prove the HID write boundary.

Then the definitive test, against the real node:

shell 
$ strace -e trace=write ./antec-display
write(3, "\0U\252\1\1\6\4\4\3\4\2\0\30", 13) = 13

One write of 13 bytes per packet. If you get permission denied, that is the udev rule, not your code.

Reference implementation — step 5
device.go 
package main

import (
	"fmt"
	"os"
	"path/filepath"
	"strings"
)

const (
	vendorID  = 0x2022
	productID = 0x0522
)

// findHidraw locates the panel by USB ID rather than by device number,
// because /dev/hidrawN is assigned in enumeration order and moves.
func findHidraw() (string, bool) {
	// HID_ID=0003:00002022:00000522 — eight hex digits per field, not four.
	needle := fmt.Sprintf(":%08X:%08X", vendorID, productID)

	entries, err := os.ReadDir("/sys/class/hidraw")
	if err != nil {
		return "", false
	}
	for _, e := range entries {
		uevent := filepath.Join("/sys/class/hidraw", e.Name(), "device", "uevent")
		b, err := os.ReadFile(uevent)
		if err != nil {
			continue
		}
		if strings.Contains(strings.ToUpper(string(b)), needle) {
			return filepath.Join("/dev", e.Name()), true
		}
	}
	return "", false
}

// send writes one HID output report. The leading zero is the report-ID byte,
// which the kernel strips because this descriptor declares no report IDs.
// One buffer, one Write: hidraw maps each write() syscall to one report.
func send(f *os.File, p [12]byte) error {
	var buf [13]byte
	copy(buf[1:], p[:])
	n, err := f.Write(buf[:])
	if err != nil {
		return err
	}
	if n != len(buf) {
		return fmt.Errorf("short write: %d of %d bytes", n, len(buf))
	}
	return nil
}

6The loop

Read both sensors, build, send, wait a second, repeat.

Connect the pieces

  1. Write readOrBlank(path string, ok bool) Reading. A missing selection or failed read returns Reading{}; a successful read returns a valid reading. Log a read failure here, where you decide to continue.
  2. Replace the one-shot main with startup discovery, one device open, and a ticker loop. Keep the selected paths and the device handle outside the loop. Read fresh values inside it.
  3. Each tick builds one packet from both readings and sends it. Check sensor-read errors separately from display-write errors so the log identifies the failing operation.

Before running it, trace a tick where the CPU read fails but the GPU reads 42.0. Which digit bytes should be blank? Should the device handle be closed?

Reach for

time.NewTicker(time.Second) rather than time.Sleep in a loop: a sleep after each update adds the work time to the interval. A ticker schedules regular ticks and can drop ticks if work is slow. Receiving from tick.C waits without spinning; step 8 adds a second event to wait for.

Error policy in a daemon

Inside the loop body, errors are not fatal. A sensor read that fails becomes a blank half and a log line. Returning an error from the loop means the service exits, systemd restarts it, and you get a restart loop instead of a recovery.

Checkpoint

Watch the panel; the numbers move. Cross-check against watch -n1 sensors. Then check top — CPU should be near zero. If it is pegged at 100%, your ticker is not in the loop or you are draining the channel wrong.

Temporarily set cpuPath to a nonexistent path after discovery while leaving cpuOK true. The CPU half should blank, the GPU should keep updating, and the log should name the failed read. Restore the path afterward.

Discovery happens once in this version. A read failure does not trigger sensor rediscovery; the reconnect logic in the next step is for the display device.

7Survive a replug

When the device goes away and comes back, reopen it instead of dying or spinning on a dead descriptor.

Right now a write error logs and then keeps writing to a file handle that will never work again. Give the device state — the open file and its path — with a method that opens it if it is not already open, and a send that closes and forgets the handle on error so the next tick re-discovers it.

Define the state transitions first

BeforeOperationAfter
f == nilDiscovery/open failsStill closed; retry later
f == nilOpen succeedsStore handle and path
f != nilWrite succeedsKeep the same handle
f != nilWrite failsClose handle; clear handle and path

Implement display, ensureOpen, close, and send against this table. Use *display receivers: these methods must update the stored object, not a copy of it. Its zero value is the closed state.

Then replace the main function's direct discovery/open/send code with var d display and d.send(p). Keep readOrBlank and orNone. A device missing at startup now follows the same retry path as an unplug.

Gotcha · re-run discovery, don't reuse the path

After a replug the device may come back as a different /dev/hidrawN, and the remembered path may now be somebody else's keyboard. Re-run discovery.

Gotcha · defer in a retry loop

defer f.Close() runs when the function returns, not when the loop iteration ends. Put it inside a reconnect loop and every reopen leaks a descriptor until the process exits. Close explicitly when you drop the handle.

Back off

After a failed send, wait two seconds before retrying. Step 8 makes that wait interruptible. Sensor failures still blank a half without resetting the device.

Checkpoint

Make the device unavailable using its USB authorization attribute. First locate the current hidraw node and use readlink -f /sys/class/hidraw/hidrawN/device to identify its parent USB device. The following uses 8-7 as an example; substitute the device belonging to the panel.

shell

sleep 2
echo 1 | sudo tee /sys/bus/usb/devices/8-7/authorized

The program should log the failure, log a reopen a couple of seconds later, and keep running. Start it while the panel is unavailable too. It should wait and recover when you authorize the panel again. Check ls /proc/PID/fd before and after several retries; the descriptor count should not keep growing.

device.go — add declarations and merge log into imports 
// display owns the open device, reopening it after an unplug.
type display struct {
	f    *os.File
	path string
}

func (d *display) ensureOpen() error {
	if d.f != nil {
		return nil
	}
	// Re-discover rather than reusing d.path: the node number can change
	// across a replug.
	path, found := findHidraw()
	if !found {
		return fmt.Errorf("no device %04X:%04X found", vendorID, productID)
	}
	f, err := os.OpenFile(path, os.O_WRONLY, 0)
	if err != nil {
		return fmt.Errorf("open %s: %w", path, err)
	}
	d.f, d.path = f, path
	log.Printf("opened %s", path)
	return nil
}

// close drops the handle. Explicit, not deferred: a defer inside a reconnect
// loop would leak one descriptor per reopen.
func (d *display) close() {
	if d.f != nil {
		d.f.Close()
		d.f, d.path = nil, ""
	}
}

func (d *display) send(p [12]byte) error {
	if err := d.ensureOpen(); err != nil {
		return err
	}
	if err := send(d.f, p); err != nil {
		d.close() // force rediscovery on the next tick
		return err
	}
	return nil
}

8Graceful shutdown

On SIGINT or SIGTERM, blank the panel and exit cleanly instead of leaving a stale number frozen on the case.

Add a second event to the loop

  1. Create a context cancelled by SIGINT or SIGTERM with signal.NotifyContext. It announces cancellation; it does not stop your loop automatically.
  2. Replace for range tick.C with for and a select: a tick performs an update; ctx.Done() performs cleanup and returns.
  3. Replace the retry sleep with another select waiting for cancellation or a two-second timer. Cancellation must leave the retry wait, then reach cleanup.
  4. On shutdown, attempt one blank packet, log any failure, and close the handle.

Trace SIGTERM during the retry wait. An unlabelled break inside a select only exits that select, not the enclosing loop. In the reference, cancellation leaves the inner select; the next loop iteration sees ctx.Done() and runs the shutdown branch.

Reach for

signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM), then select over ctx.Done() and your ticker channel.

Gotcha · if you roll it manually, buffer the channel

signal.Notify on an unbuffered channel drops signals when nobody is receiving at that instant. make(chan os.Signal, 1). go vet reports this.

Gotcha · defer does not run on os.Exit

Any cleanup behind a defer is skipped by os.Exit, and log.Fatal calls os.Exit for you. If your blanking lives in a defer and something later calls log.Fatal, the panel keeps its stale reading. Blank explicitly on the shutdown path.

Checkpoint

Build with go build -o antec-display . and run ./antec-display in the foreground. Press Ctrl-C: the panel should show --.- within about a second and the process should exit 0 — check with echo $?. Then kill -TERM the PID and confirm identical behaviour.

Then kill -KILL it. The panel keeps its stale reading, because SIGKILL cannot be caught by anything.

Repeat SIGTERM while the display is unavailable and the program is backing off. It should exit without waiting for the two-second timer; blanking may fail because the device is absent. Cancellation wakes the channel waits, but does not interrupt an already-running file read or write.

Reference implementation — step 8
main.go — replace imports and main; keep readOrBlank and orNone 
import (
	"context"
	"log"
	"os"
	"os/signal"
	"syscall"
	"time"
)

func main() {
	log.SetFlags(0) // journald already timestamps every line

	cpuPath, cpuOK := findCPU()
	gpuPath, gpuOK := findGPU()
	log.Printf("cpu sensor: %s", orNone(cpuPath, cpuOK))
	log.Printf("gpu sensor: %s", orNone(gpuPath, gpuOK))
	if !cpuOK && !gpuOK {
		log.Fatal("no CPU or GPU sensor found under /sys/class/hwmon")
	}

	ctx, stop := signal.NotifyContext(context.Background(),
		os.Interrupt, syscall.SIGTERM)
	defer stop()

	var d display
	tick := time.NewTicker(time.Second)
	defer tick.Stop()

	for {
		select {
		case <-ctx.Done():
			log.Print("shutting down, blanking panel")
			if err := d.send(buildPacket(Reading{}, Reading{})); err != nil {
				log.Printf("blank display: %v", err)
			}
			d.close()
			return

		case <-tick.C:
			p := buildPacket(
				readOrBlank(cpuPath, cpuOK),
				readOrBlank(gpuPath, gpuOK),
			)
			if err := d.send(p); err != nil {
				log.Printf("display: %v", err)
				// Back off so a missing device doesn't flood the journal.
				select {
				case <-ctx.Done():
				case <-time.After(2 * time.Second):
				}
			}
		}
	}
}

A static binary, a udev rule, a systemd unit, and a panel that comes back by itself after a reboot.

For this standard-library Linux program, CGO_ENABLED=0 produces a static binary. It still needs the kernel's sensor files and device node. Keep debug information while learning; -ldflags="-s -w" is an optional size reduction later.

Reuse the repo's udev rule and systemd unit; set ExecStart to your binary. ProtectSystem=strict makes the filesystem read-only except /dev, /proc and /sys; this program reads sysfs and writes the device node. Restart=always restarts it after process exit, but unplug recovery remains the program's responsibility while it is running.
