Before you start

Read the foundations page first if you have not. In particular, do the shell warm-up — driving the panel with printf and dd takes thirty seconds and permanently separates “my Go is wrong” from “my understanding of the device is wrong”.

Everything here is standard library. No modules to add, no cgo, no build tags. Searching for “USB HID Go” will push you toward gousb or karalabe/hid; both drag in a C toolchain and neither is needed.

mkdir -p ~/src/antec-display && cd ~/src/antec-display

How each step is laid out

Every step states a goal, points at the specific standard-library calls to reach for, warns you about what will go wrong, and gives you a way to prove it worked. A reference implementation sits behind a collapsed block at the end of each step — try the step before opening it.

1The packet builder

Turn two temperatures into the twelve bytes from the protocol table. No files, no device, no I/O at all — and therefore fully testable before you own any of the hard parts.

You need two things: a function that splits one temperature into its three digit bytes, and a function that assembles the full packet and checksums it. Both halves of the panel can be absent, so your digit function needs a way to express “no reading” and return 0xEE 0xEE 0xEE. Go has no option type; a small struct carrying a value and a validity flag reads better here than a *float64, and it keeps buildPacket down to two parameters.

Reach for

[12]byte and [3]byte — fixed arrays, not slices. The packet is always exactly twelve bytes and saying so in the type removes a whole class of bug. copy() to move digit triples into place. %X and %02X for eyeballing output.

Gotcha · you cannot slice a returned array

copy(p[5:8], digits(cpu)[:]) does not compile: invalid operation: cannot slice unaddressable value. A function's return value has no address, and slicing an array requires one. Assign it to a variable first, then slice that.

The checksum

0x55 + 0xAA + 0x01 already exceeds a byte. Accumulate in a byte and Go wraps silently — which, because the spec wants exactly sum & 0xFF, happens to give the right answer. It works by luck rather than by design, so accumulate in a uint32 and convert once at the end. It reads as deliberate, and it is the same code you would have to write in Rust, where the sloppy version panics.

Reaching for the wrong tool

Do not build this with strconv, fmt.Sprintf or a string. The digits are values, not characters — 44.3 °C is 0x04 0x04 0x03, not "443". Anything that produces text is the wrong shape.

Checkpoint

Write a table test with the two vectors from the protocol page. They are exact:

expected 
44.3 / 42.0   ->  55 AA 01 01 06 04 04 03 04 02 00 18
blank / blank ->  55 AA 01 01 06 EE EE EE EE EE EE 9B

Add edge cases while you are there: 0.0 gives 00 00 00, 99.9 gives 09 09 09, 150.0 clamps to 09 09 09, and -5.0 clamps to 00 00 00. Finish with a self-consistency assertion that byte 11 really equals the low byte of the sum of bytes 0–10 — it will catch a typo in your header long after you have stopped looking at it.

Reference implementation — step 1
packet.go 
package main

// Reading is a temperature that may or may not be available. Go has no
// option type; an explicit Valid flag beats a *float64 here because the
// zero value (absent) is the safe default.
type Reading struct {
	Celsius float64
	Valid   bool
}

var blank = [3]byte{0xEE, 0xEE, 0xEE}

// digits splits a reading into tens, ones and tenths.
func digits(r Reading) [3]byte {
	if !r.Valid {
		return blank
	}
	c := r.Celsius
	if c < 0 {
		c = 0
	}
	if c > 99.9 {
		c = 99.9
	}
	v := int(c*10 + 0.5) // round, then work in tenths
	return [3]byte{byte(v / 100), byte(v / 10 % 10), byte(v % 10)}
}

func buildPacket(cpu, gpu Reading) [12]byte {
	var p [12]byte
	p[0], p[1] = 0x55, 0xAA
	p[2], p[3], p[4] = 0x01, 0x01, 0x06

	// Assign first: digits(cpu)[:] would not compile.
	c, g := digits(cpu), digits(gpu)
	copy(p[5:8], c[:])
	copy(p[8:11], g[:])

	var sum uint32
	for _, b := range p[:11] {
		sum += uint32(b)
	}
	p[11] = byte(sum)
	return p
}
packet_test.go 
package main

import "testing"

func TestBuildPacket(t *testing.T) {
	cases := []struct {
		name     string
		cpu, gpu Reading
		want     [12]byte
	}{
		{"vector", Reading{44.3, true}, Reading{42.0, true},
			[12]byte{0x55, 0xAA, 0x01, 0x01, 0x06, 4, 4, 3, 4, 2, 0, 0x18}},
		{"blank", Reading{}, Reading{},
			[12]byte{0x55, 0xAA, 0x01, 0x01, 0x06,
				0xEE, 0xEE, 0xEE, 0xEE, 0xEE, 0xEE, 0x9B}},
	}
	for _, tc := range cases {
		got := buildPacket(tc.cpu, tc.gpu)
		if got != tc.want {
			t.Errorf("%s:\n got %X\nwant %X", tc.name, got, tc.want)
		}
		var sum uint32
		for _, b := range got[:11] {
			sum += uint32(b)
		}
		if byte(sum) != got[11] {
			t.Errorf("%s: checksum %02X does not match body", tc.name, got[11])
		}
	}
}

func TestDigitsClamp(t *testing.T) {
	cases := []struct {
		in   float64
		want [3]byte
	}{
		{0.0, [3]byte{0, 0, 0}},
		{99.9, [3]byte{9, 9, 9}},
		{150.0, [3]byte{9, 9, 9}},
		{-5.0, [3]byte{0, 0, 0}},
	}
	for _, tc := range cases {
		if got := digits(Reading{tc.in, true}); got != tc.want {

		}
	}
}

2Read one temperature

Get 47.1 out of /sys/class/hwmon/hwmon4/temp1_input. Hardcode the path — you are going to break it deliberately in step 3.

Three lines of real work: read the file, trim it, parse it, divide by a thousand. The value of doing it as its own step is that it forces you to decide how errors travel through this program before there is anything complicated in the way.

Reach for

os.ReadFile — not os.Open and a Scanner; these files are a handful of bytes. strings.TrimSpace, strconv.Atoi, and fmt.Errorf with %w to wrap.

Gotcha · include the path in every error

os.ReadFile returns a *PathError, so its message names the file. strconv.Atoi's does not — you get strconv.Atoi: parsing "47125\n": invalid syntax, and once this program is opening a dozen sysfs paths that is not enough to act on. Wrap both with the path: fmt.Errorf("read %s: %w", path, err). You will be reading these messages out of journalctl at some point, with no debugger.

Gotcha · the trailing newline

The file contains 47125\n. Forget TrimSpace and Atoi fails with invalid syntax, which does not mention whitespace and reads like the file is corrupt. Trim on read, always, as a reflex.

Gotcha · integer division eats the decimal

47125 / 1000 is 47, silently. You need float64(milli) / 1000. You could also skip floats entirely and work in tenths — (milli + 50) / 100 gives you 471 directly, which is exactly what the digit splitter wants and has no rounding subtleties at all. Either is fine; pick on purpose.

Checkpoint

cat /sys/class/hwmon/hwmon4/temp1_input prints something like 47125; your program prints 47.1. Cross-check against sensors and its Tctl line.

Then break it on purpose twice: point it at a path that does not exist, and at .../name, which exists but will not parse. Both should produce one clean line naming the file. If either produces a panic or a bare invalid syntax, fix that now — this is the error plumbing every later step rides on.

Reference implementation — step 2
sensors.go 
package main

import (
	"fmt"
	"os"
	"strconv"
	"strings"
)

// readSysfs reads a small sysfs file and trims the trailing newline.
// Every read in this program goes through here so the trim can't be forgotten.
func readSysfs(path string) (string, error) {
	b, err := os.ReadFile(path)
	if err != nil {
		return "", err // *PathError already names the file
	}
	return strings.TrimSpace(string(b)), nil
}

// readTemp returns degrees Celsius from a hwmon tempN_input file.
func readTemp(path string) (float64, error) {
	s, err := readSysfs(path)
	if err != nil {
		return 0, fmt.Errorf("read temperature: %w", err)
	}
	milli, err := strconv.Atoi(s)
	if err != nil {
		return 0, fmt.Errorf("parse %s: %w", path, err)
	}
	return float64(milli) / 1000, nil
}

3Find the sensors

Replace the hardcoded path with a scan: given a driver name like k10temp and a preferred label like Tctl, return the matching tempN_input path.

First, see the problem: reboot, or run sudo udevadm trigger, then check whether hwmon4 is still k10temp. Numbering is assigned in driver-probe order and moves. If your program quietly starts showing your network card's temperature, that is why.

The shape: enumerate /sys/class/hwmon/hwmon*, read each name, keep the ones matching the driver you want, enumerate their temp*_input files, read the matching _label beside each, and return the one whose label you asked for — falling back to the first input if none matched.

Reach for

filepath.Glob handles both enumerations and saves you a manual ReadDir-and-filter. filepath.Join to build paths. strings.TrimSuffix to turn temp1_input into temp1_label. strings.EqualFold so label matching is not case-sensitive.

Gotcha · do not filter on IsDir

The highest-severity silent failure in this project. Every entry under /sys/class/hwmon is a symlink into /sys/devices/…, and os.ReadDir returns DirEntry values whose IsDir() reports the type of the link, not its target. Filter on e.IsDir() and you get zero results, no error, and nothing to grep for.

filepath.Glob sidesteps this entirely, which is a good reason to prefer it here. If you do use ReadDir, either stat the resolved path with os.Stat (which follows links) or simply try to read name and skip entries where that fails.

Gotcha · numbering has holes, and sorts wrong

k10temp here exposes temp1, temp3, temp4 — there is no temp2. Any for i := 1; i <= n; i++ loop is wrong. Enumerate, never count.

And filepath.Glob returns results sorted lexically, so hwmon10 sorts before hwmon2. It does not bite on this machine, which only reaches hwmon8, but do not write code that depends on the order.

Gotcha · labels are optional

spd5118 and ath12k_hwmon have no _label files at all. A missing label is normal. Treat the read failure as an empty string and move on; do not propagate it as an error, or a RAM sensor you do not care about will abort your whole scan.

Checkpoint

Print everything you found — directory, driver name, and each input with its label — and diff it against the shell:

shell 
for d in /sys/class/hwmon/hwmon*; do echo "$d $(cat $d/name)"; done

Two specific things to confirm. Did you find k10temp's temp3 and temp4 despite there being no temp2? And did you get any results at all — an empty list means the symlink trap.

Reference implementation — step 3
sensors.go (continued) 
import (
	"path/filepath"
	"sort"
)

type sensor struct {
	path  string // .../tempN_input
	label string // "Tctl", "edge", … or "" when the device exposes none
}

// tempInputs lists every temperature sensor in one hwmon directory.
func tempInputs(dir string) []sensor {
	// Glob, not ReadDir: entries under /sys/class/hwmon are symlinks and
	// DirEntry.IsDir() reports false for all of them.
	matches, err := filepath.Glob(filepath.Join(dir, "temp*_input"))
	if err != nil {
		return nil
	}
	sort.Strings(matches)

	out := make([]sensor, 0, len(matches))
	for _, p := range matches {
		// A missing label file is normal, not an error.
		label, _ := readSysfs(strings.TrimSuffix(p, "_input") + "_label")
		out = append(out, sensor{path: p, label: label})
	}
	return out
}

// hwmonByDriver returns every hwmon directory belonging to a driver.
func hwmonByDriver(driver string) []string {
	dirs, _ := filepath.Glob("/sys/class/hwmon/hwmon*")
	var out []string
	for _, d := range dirs {
		if name, err := readSysfs(filepath.Join(d, "name")); err == nil && name == driver {
			out = append(out, d)
		}
	}
	return out
}

4Pick the right GPU

Given two amdgpu instances, choose the discrete card and not the integrated one.

A Ryzen desktop chip with integrated graphics gives you two amdgpu hwmon directories. One is your RX 9070; the other is the iGPU sitting at idle forever. Pick wrong and the panel shows the iGPU's idle temperature from now on.

PathInputsLabelsWhich
hwmon23edge, junction, memDiscrete
hwmon31edgeiGPU

The heuristic: a discrete card reports edge, junction and memory; an integrated one reports only edge. So among candidates for a driver, take the one with the most temperature inputs. Fold this into the sensor finder from step 3 — the same rule is harmless for k10temp, where there is only ever one instance.

It's a heuristic, so say what you picked

This is a guess that happens to be right on every machine anyone has tested. It could be wrong on yours. One log.Printf at startup naming the chosen paths makes a wrong guess diagnosable from the journal.

Checkpoint

Your finder should land on hwmon4/temp1_input (Tctl) for the CPU and hwmon2/temp1_input (edge) for the GPU — not hwmon3. Confirm the number is plausible against sensors, then load the GPU with something and watch it move.

Reference implementation — step 4
sensors.go (continued) 
// findSensor picks a temperature input for a driver, preferring the first
// label in preferred that exists. Among several instances of the same driver
// (a discrete GPU and an iGPU both bind amdgpu) the one exposing the most
// sensors wins — a discrete card reports edge+junction+mem, an iGPU only edge.
func findSensor(driver string, preferred ...string) (string, bool) {
	var best []sensor
	for _, dir := range hwmonByDriver(driver) {
		if s := tempInputs(dir); len(s) > len(best) {
			best = s
		}
	}
	if len(best) == 0 {
		return "", false
	}
	for _, want := range preferred {
		for _, s := range best {
			if strings.EqualFold(s.label, want) {
				return s.path, true
			}
		}
	}
	return best[0].path, true
}

// findCPU and findGPU encode the per-vendor preferences in one place.
func findCPU() (string, bool) {
	if p, ok := findSensor("k10temp", "Tctl"); ok {
		return p, true
	}
	return findSensor("coretemp", "Package id 0")
}

func findGPU() (string, bool) {
	if p, ok := findSensor("amdgpu", "edge"); ok {
		return p, true
	}
	return findSensor("nvidia")
}

5Find the device and write to it

Locate your /dev/hidrawN by USB ID, then put a number on the panel from your own code.

Two halves. Discovery is the same directory-scanning shape as step 3 with a different matcher: walk /sys/class/hidraw/*, read each device/uevent, and look for the HID_ID line.

Gotcha · eight hex digits, not four

HID_ID=0003:00002022:00000522. The vendor and product fields are zero-padded to eight digits. Searching for "2022:0522" matches nothing, silently. Build the needle with fmt.Sprintf(":%08X:%08X", vid, pid) and compare case-insensitively — the kernel writes lowercase hex.

This exact bug shipped in the first draft of the Python version in this repo.

The write half is where the two rules from the foundations page get enforced. Your buffer is thirteen bytes — a leading 0x00 report ID, then the packet — and it goes out in a single Write.

Reach for

os.OpenFile(path, os.O_WRONLY, 0). Not os.Create, which adds O_CREAT|O_TRUNC — harmless on a character device but wrong, and it will fail confusingly under the hardened systemd unit in step 9. Not os.O_RDWR either; you never read from this device, and the IN endpoint would block if you tried.

Reaching for the wrong tool

bufio.NewWriter around the device. Here it silently breaks the protocol: hidraw maps one write() syscall to one HID report, so buffering can split your report or hold it until a flush you forgot. *os.File.Write is already exactly one syscall. Use it directly.

Same trap, different shape: writing the header and the body in two calls.

Checkpoint

Aim at a scratch file before the real device — you need no root for this:

shell 
$ ./antec-display --out /tmp/panel.bin
$ wc -c /tmp/panel.bin
13 /tmp/panel.bin
$ hexdump -C /tmp/panel.bin
00000000  00 55 aa 01 01 06 04 04  03 04 02 00 18

Exactly 13 bytes. Zero means an unflushed buffer; 14 means a stray newline crept in.

Then the definitive test, against the real node:

shell 
$ strace -e trace=write ./antec-display
write(3, "\0U\252\1\1\6\4\4\3\4\2\0\30", 13) = 13

One write of 13 bytes per packet. Seeing the syscall is better proof than seeing the right number on the panel, because a torn report can still occasionally look correct. If you get permission denied, that is the udev rule, not your code.

Reference implementation — step 5
device.go 
package main

import (
	"fmt"
	"os"
	"path/filepath"
	"strings"
)

const (
	vendorID  = 0x2022
	productID = 0x0522
)

// findHidraw locates the panel by USB ID rather than by device number,
// because /dev/hidrawN is assigned in enumeration order and moves.
func findHidraw() (string, bool) {
	// HID_ID=0003:00002022:00000522 — eight hex digits per field, not four.
	needle := fmt.Sprintf(":%08X:%08X", vendorID, productID)

	entries, err := os.ReadDir("/sys/class/hidraw")
	if err != nil {
		return "", false
	}
	for _, e := range entries {
		uevent := filepath.Join("/sys/class/hidraw", e.Name(), "device", "uevent")
		b, err := os.ReadFile(uevent)
		if err != nil {
			continue
		}
		if strings.Contains(strings.ToUpper(string(b)), needle) {
			return filepath.Join("/dev", e.Name()), true
		}
	}
	return "", false
}

// send writes one HID output report. The leading zero is the report-ID byte,
// which the kernel strips because this descriptor declares no report IDs.
// One buffer, one Write: hidraw maps each write() syscall to one report.
func send(f *os.File, p [12]byte) error {
	var buf [13]byte
	copy(buf[1:], p[:])
	n, err := f.Write(buf[:])
	if err != nil {
		return err
	}
	if n != len(buf) {
		return fmt.Errorf("short write: %d of %d bytes", n, len(buf))
	}
	return nil
}

6The loop

Read both sensors, build, send, wait a second, repeat. Now it is a program rather than a script.

The mechanics are trivial; the decisions are about failure: a sensor read that fails on one tick must not kill the process, and a missing sensor at startup must not stop the other half of the panel from working.

Reach for

time.NewTicker(time.Second) rather than time.Sleep in a loop. Sleep drifts by however long your work took; a ticker fires on a fixed schedule. At 1 Hz nobody would notice, but the ticker also gives you a channel, which is what makes step 8's select possible without restructuring anything.

Error policy in a daemon

Inside the loop body, errors are not fatal. A sensor read that fails becomes a blank half and a log line. Returning an error from the loop means the service exits, systemd restarts it, and you get a restart loop instead of a recovery — which is worse than the original problem, and harder to diagnose because the logs scroll.

Rate-limit your complaints, too. A permanently missing sensor should not write one line per second to the journal forever.

Checkpoint

Watch the panel for ten seconds; the numbers move. Cross-check against watch -n1 sensors. Then check top — CPU should be indistinguishable from zero. If it is pegged at 100%, your ticker is not in the loop or you are draining the channel wrong.

Reference implementation — step 6
main.go 
package main

import (
	"log"
	"os"
	"time"
)

func readOrBlank(path string, ok bool) Reading {
	if !ok {
		return Reading{}
	}
	c, err := readTemp(path)
	if err != nil {
		log.Printf("sensor: %v", err)
		return Reading{}
	}
	return Reading{Celsius: c, Valid: true}
}

func main() {
	cpuPath, cpuOK := findCPU()
	gpuPath, gpuOK := findGPU()
	log.Printf("cpu sensor: %s", orNone(cpuPath, cpuOK))
	log.Printf("gpu sensor: %s", orNone(gpuPath, gpuOK))
	if !cpuOK && !gpuOK {
		log.Fatal("no CPU or GPU sensor found under /sys/class/hwmon")
	}

	devPath, found := findHidraw()
	if !found {
		log.Fatal("no device 2022:0522 found")
	}
	f, err := os.OpenFile(devPath, os.O_WRONLY, 0)
	if err != nil {
		log.Fatalf("open %s: %v", devPath, err)
	}
	defer f.Close()
	log.Printf("opened %s", devPath)

	tick := time.NewTicker(time.Second)
	defer tick.Stop()
	for range tick.C {
		p := buildPacket(readOrBlank(cpuPath, cpuOK), readOrBlank(gpuPath, gpuOK))
		if err := send(f, p); err != nil {
			log.Printf("write: %v", err) // step 7 makes this recover
		}
	}
}

func orNone(path string, ok bool) string {
	if !ok {
		return "none"
	}
	return path
}

7Survive a replug

When the device goes away and comes back, reopen it instead of dying or spinning on a dead descriptor.

Right now a write error logs and then keeps writing to a file handle that will never work again. Give the device a small piece of state — the open file and its path — with a method that opens it if it is not already open, and a send that closes and forgets the handle on error so the next tick re-discovers it.

Gotcha · re-run discovery, don't reuse the path

After a replug the device may well come back as a different /dev/hidrawN. Reopening the remembered path gets you a working file handle for somebody else's keyboard. Discovery is cheap; run it again.

Gotcha · defer in a retry loop

defer f.Close() runs when the function returns, not when the loop iteration ends. Put it inside a reconnect loop and every reopen leaks a descriptor until the process exits. Close explicitly when you drop the handle.

Back off

If the device stays gone, retrying every second forever is fine and cheap. Retrying in a tight loop with no delay is not — you will fill the journal in minutes. A couple of seconds between attempts is plenty, and worth logging the first failure but not the hundredth.

Checkpoint

Make the device go away. Physically unplug the internal header, or do it in software:

shell 
# find the USB path from HID_PHYS in the uevent file — here, 1-7
echo 0 | sudo tee /sys/bus/usb/devices/1-7/authorized
sleep 2
echo 1 | sudo tee /sys/bus/usb/devices/1-7/authorized

The program should log the failure, log a reopen a couple of seconds later, and keep running throughout. If it exits, the error is still escaping the loop.

Reference implementation — step 7
device.go (continued) 
// display owns the open device, reopening it after an unplug.
type display struct {
	f    *os.File
	path string
}

func (d *display) ensureOpen() error {
	if d.f != nil {
		return nil
	}
	// Re-discover rather than reusing d.path: the node number can change
	// across a replug.
	path, found := findHidraw()
	if !found {
		return fmt.Errorf("no device %04X:%04X found", vendorID, productID)
	}
	f, err := os.OpenFile(path, os.O_WRONLY, 0)
	if err != nil {
		return fmt.Errorf("open %s: %w", path, err)
	}
	d.f, d.path = f, path
	log.Printf("opened %s", path)
	return nil
}

// close drops the handle. Explicit, not deferred: a defer inside a reconnect
// loop would leak one descriptor per reopen.
func (d *display) close() {
	if d.f != nil {
		d.f.Close()
		d.f, d.path = nil, ""
	}
}

func (d *display) send(p [12]byte) error {
	if err := d.ensureOpen(); err != nil {
		return err
	}
	if err := send(d.f, p); err != nil {
		d.close() // force rediscovery on the next tick
		return err
	}
	return nil
}

8Graceful shutdown

On SIGINT or SIGTERM, blank the panel and exit cleanly instead of leaving a stale number frozen on the case.

Nothing refreshes the display but you. Kill the process and whatever was last written stays there indefinitely, which looks exactly like a hung machine. Send the blank vector on the way out.

Reach for

signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM), then select over ctx.Done() and your ticker channel. This is the modern form and it composes: you get a context you could pass to anything else that needs to stop.

Gotcha · if you roll it manually, buffer the channel

signal.Notify on an unbuffered channel drops signals when nobody is receiving at that instant. make(chan os.Signal, 1). The runtime does not block to deliver, and go vet will tell you about this one.

Gotcha · defer does not run on os.Exit

Any cleanup behind a defer is skipped by os.Exit, and log.Fatal calls os.Exit for you. If your blanking lives in a defer and something later calls log.Fatal, the panel keeps its stale reading. Blank explicitly on the shutdown path.

Before you read the Rust page

This step is about fifteen lines of standard library. Rust's standard library has no signal handling at all — no os/signal equivalent, at any level. Doing this in Rust means adding your first external crate, or pushing the problem out to systemd. It is the one place in this project where Go is straightforwardly ahead.

Checkpoint

Run it in the foreground and press Ctrl-C: the panel should show --.- within about a second and the process should exit 0 — check with echo $?. Then kill -TERM the PID and confirm identical behaviour.

Then kill -KILL it. The panel keeps its stale reading, because SIGKILL cannot be caught by anything. That is not a bug in your program.

Reference implementation — step 8
main.go (revised) 
package main

import (
	"context"
	"log"
	"os"
	"os/signal"
	"syscall"
	"time"
)

func main() {
	log.SetFlags(0) // journald already timestamps every line

	cpuPath, cpuOK := findCPU()
	gpuPath, gpuOK := findGPU()
	log.Printf("cpu sensor: %s", orNone(cpuPath, cpuOK))
	log.Printf("gpu sensor: %s", orNone(gpuPath, gpuOK))
	if !cpuOK && !gpuOK {
		log.Fatal("no CPU or GPU sensor found under /sys/class/hwmon")
	}

	ctx, stop := signal.NotifyContext(context.Background(),
		os.Interrupt, syscall.SIGTERM)
	defer stop()

	var d display
	tick := time.NewTicker(time.Second)
	defer tick.Stop()

	for {
		select {
		case <-ctx.Done():
			log.Print("shutting down, blanking panel")
			d.send(buildPacket(Reading{}, Reading{})) // best effort
			d.close()
			return

		case <-tick.C:
			p := buildPacket(
				readOrBlank(cpuPath, cpuOK),
				readOrBlank(gpuPath, gpuOK),
			)
			if err := d.send(p); err != nil {
				log.Printf("display: %v", err)
				// Back off so a missing device doesn't flood the journal.
				select {
				case <-ctx.Done():
				case <-time.After(2 * time.Second):
				}
			}
		}
	}
}

9Ship it

A static binary, a udev rule, a systemd unit, and a panel that comes back by itself after a reboot.

shell 
CGO_ENABLED=0 go build -ldflags="-s -w" -o antec-display .
ldd antec-display     # "not a dynamic executable"

CGO_ENABLED=0 gives you one file: no interpreter, no shared libraries, nothing to install alongside it. Compare that against the Python version in this repo, which needs a working Python 3 on the box forever.

The repo already has a udev rule and a systemd unit written for the Python daemon. Reuse both — only ExecStart changes. The unit's hardening is worth reading rather than copying blind: ProtectSystem=strict makes the whole filesystem read-only except /dev, /proc and /sys, which is exactly the access this program needs and nothing else.

shell 
sudo install -m0755 antec-display /usr/local/bin/antec-display
sudo cp 99-antec-display.rules /etc/udev/rules.d/
sudo cp antec-display.service /etc/systemd/system/
sudo sed -i 's|^ExecStart=.*|ExecStart=/usr/local/bin/antec-display|' \
  /etc/systemd/system/antec-display.service
sudo udevadm control --reload-rules && sudo udevadm trigger --subsystem-match=hidraw
sudo systemctl daemon-reload
sudo systemctl enable --now antec-display
You do not need a logging library

Under systemd, anything your process writes to stdout or stderr is captured by journald with correct timestamps and metadata. log.Printf is sufficient — no zap, no logrus, no slog handler configuration. log.SetFlags(0) is worth setting so you do not print a timestamp next to journald's own.

Optional, if you want the practice

A few flags via the flag package rather than cobra: --out to write to a file instead of the device (you probably built this in step 5), --once to send one packet and exit, --interval, and explicit sensor path overrides for machines where the heuristic guesses wrong.

Checkpoint

systemctl status antec-display is clean and journalctl -u antec-display -f shows your two startup lines naming the sensors it chose — which also proves plain log.Printf reaches the journal.

Restart it twice. Then systemctl stop and confirm the panel blanks rather than freezing — that is step 8 working through systemd's SIGTERM.

Then reboot. If it finds the right hidraw node and the right hwmon directories on a machine where the numbering has shifted, the discovery code from steps 3 and 5 works.
