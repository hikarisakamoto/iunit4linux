0Orientation

Most of what makes Rust hard to start is not used in this project.

What you are allowed to skip

You will not need any of the following:

  • skipasync/await, futures, tokio. This program is one thread that sleeps for a second.
  • skipThreads, channels, Mutex, Send/Sync. One shared flag appears in step 8, as boilerplate.
  • skipLifetime annotations — the <'a> things. You will never write one here, because the program returns owned values everywhere.
  • skipWriting traits, generics, trait bounds. You will use three traits from the standard library and author none.
  • skipCustom error types, thiserror, From impls. One boxed error type carries you the whole way.
  • skipunsafe, FFI, libc, bindgen. None; the device is a file.
  • skipRc, RefCell, interior mutability, smart pointers. None.

If you are working through The Rust Programming Language alongside this: chapters 1–9, 11 and 13 cover everything used here. Chapter 10 (generics, traits, lifetimes), 15 (smart pointers) and 16 (concurrency) can wait.

1The packet builder

Turn two temperatures into the twelve-byte packet. Pure functions, so fully testable.

Two functions: one that splits a single temperature into its three digit bytes, one that assembles and checksums the packet. Either half of the panel can be absent, so the digit function needs to express “no reading” and return 0xEE 0xEE 0xEE.

That is Option<f32>, handled with match, a switch that must cover every case.

Reach for

[u8; 12] and [u8; 3] — fixed-size arrays, not Vec. const for the blank triple. f32::clamp and f32::round. copy_from_slice to drop a triple into place. {:02X?} to print an array as hex.

Gotcha · a u8 checksum panics in debug builds

Accumulate in a u8 and a debug build panics with attempt to add with overflow, while a release build wraps to the right answer. Sum into a u32 and narrow once with as u8.

Gotcha · as has two different behaviours

300.7_f32 as u8 gives 255 — float-to-integer casts saturate. 300_i32 as u8 gives 44 — integer-to-integer casts wrap.

Clamp before you cast.

Reaching for the wrong tool

Do not build this as a String: the digits are values, not characters (44.3 °C is 0x04, not b'4'), and 0xEE 0xEE 0xEE is not valid UTF-8, so the compiler refuses it anyway.

Checkpoint

Write tests. In Rust they live in the same file, in a #[cfg(test)] mod tests block at the bottom, and cargo test runs them.

expected 
44.3 / 42.0   ->  55 AA 01 01 06 04 04 03 04 02 00 18
blank / blank ->  55 AA 01 01 06 EE EE EE EE EE EE 9B

Add clamping cases: 0.0 gives [0,0,0], 99.9 gives [9,9,9], 150.0 clamps to [9,9,9], -5.0 to [0,0,0]. Then a self-consistency test that byte 11 equals the low byte of the sum of bytes 0–10.

Run the tests in both profiles — cargo test and cargo test --release. If they disagree, you have the u8 overflow bug.

Reference implementation — step 1
src/main.rs 
const BLANK: [u8; 3] = [0xEE, 0xEE, 0xEE];

/// A temperature that may not be available. `None` blanks half the panel.
type Reading = Option<f32>;

fn digits(r: Reading) -> [u8; 3] {
    match r {
        None => BLANK,
        Some(c) => {
            // Clamp before casting: a 3-digit temperature has nowhere to go,
            // and `as` saturates for floats but wraps for integers.
            let tenths = (c.clamp(0.0, 99.9) * 10.0).round() as u32;
            [
                (tenths / 100) as u8,
                (tenths / 10 % 10) as u8,
                (tenths % 10) as u8,
            ]
        }
    }
}

fn build_packet(cpu: Reading, gpu: Reading) -> [u8; 12] {
    let mut p = [0u8; 12];
    p[0..2].copy_from_slice(&[0x55, 0xAA]);
    p[2..5].copy_from_slice(&[0x01, 0x01, 0x06]);
    p[5..8].copy_from_slice(&digits(cpu));
    p[8..11].copy_from_slice(&digits(gpu));

    // Sum in u32: eleven bytes overflow a u8, which panics in debug builds.
    let sum: u32 = p[..11].iter().map(|&b| b as u32).sum();
    p[11] = sum as u8;
    p
}

mod tests {
    use super::*;

    #[test]
    fn known_vectors() {
        assert_eq!(
            build_packet(Some(44.3), Some(42.0)),

    #[test]
    fn clamps_out_of_range() {
        assert_eq!(digits(Some(0.0)), [0, 0, 0]);
        assert_eq!(digits(Some(99.9)), [9, 9, 9]);
        assert_eq!(digits(Some(150.0)), [9, 9, 9]);
        assert_eq!(digits(Some(-5.0)), [0, 0, 0]);

    }
}

2Read one temperature

Get 47.1 out of /sys/class/hwmon/hwmon6/temp1_input. Hardcode the path — you will break it deliberately in step 3.

Read the file, trim it, parse it, divide by a thousand. Two of the four operations can fail, so this is where you meet Result and ?: if the operation failed, ? returns the error from the current function; otherwise it yields the value. The function, including fn main(), must return a Result.

Reach for

std::fs::read_to_string, .trim(), .parse(). For the error type, use Box<dyn Error>: it accepts any error, including a plain String, which is what lets you attach the file path.

Why Box<dyn Error>

This function produces two error types — an io::Error from reading and a ParseIntError from parsing — and ? cannot unify them. Box<dyn Error> holds either.

Gotcha · the trailing newline

Skip .trim() and .parse() fails with invalid digit found in string, which does not mention whitespace.

Gotcha · you cannot return what .trim() gives you

read_to_string hands you a String that owns a heap buffer. .trim() hands back a &str — a view into that buffer, not a copy. When the function returns, the String is dropped and the buffer freed, so the view would point at nothing. Rust refuses: cannot return value referencing local variable.

The fix is .trim().to_string(), which allocates an owned string. Coming from Go, where slicing a string is free, that feels wasteful; it is one small allocation per second.

Gotcha · integer division eats the decimal

47125 / 1000 is 47. You need milli as f32 / 1000.0. You could also avoid floats: (milli + 50) / 100 gives 471 tenths directly, which is what the digit splitter wants.

Checkpoint

cat /sys/class/hwmon/hwmon6/temp1_input prints something like 47125; your program prints 47.1. Cross-check with sensors.

Then break it twice on purpose: point it at a path that does not exist, and at .../name, which exists but will not parse. Both should print one clean line naming the file. An error returned from main is formatted with Debug, so the String from map_err appears in quotes: Error: "read /sys/…/temp1_input: No such file or directory (os error 2)".

Reference implementation — step 2
src/main.rs 
use std::error::Error;
use std::fs;
use std::path::Path;

/// Reads a small sysfs file and trims the trailing newline. Every sysfs read
/// goes through here so the trim cannot be forgotten.
fn read_sysfs(path: &Path) -> Result<String, Box<dyn Error>> {
    let raw = fs::read_to_string(path).map_err(|e| format!("read {}: {e}", path.display()))?;
    // to_string() because `raw` dies at the end of this function and a
    // &str into it would dangle.
    Ok(raw.trim().to_string())
}

/// Degrees Celsius from a hwmon tempN_input file, which holds millidegrees.
fn read_temp(path: &Path) -> Result<f32, Box<dyn Error>> {
    let text = read_sysfs(path)?;
    let milli: i32 = text
        .parse()
        .map_err(|e| format!("parse {}: {e}", path.display()))?;
    Ok(milli as f32 / 1000.0)
}

3Find the sensors

Replace the hardcoded path with a scan: given a driver name like k10temp, find its tempN_input files and their labels.

Before writing it, check the premise: reboot, or run sudo udevadm trigger, and check whether hwmon6 is still k10temp.

The shape: read /sys/class/hwmon, and for each entry read its name file and keep the ones matching the driver you want. Then in each of those directories, find the files called temp*_input and read the matching _label beside each.

Reach for

fs::read_dir, PathBuf, Path::join, Vec. str::starts_with and ends_with for matching filenames. .ok() to turn a Result you do not care about into an Option. A plain struct to pair a path with its label — with #[derive(Debug)] on it so you can print it with {:?}.

Gotcha · read_dir gives you two layers of Result

fs::read_dir(path) returns a Result — opening a directory can fail — and iterating it yields another Result per entry, because reading can fail partway through.

Two idioms: let entry = entry?; inside the loop propagates each error; .flatten() on the iterator drops failed entries, which is right here — an unreadable entry in /sys/class/hwmon is one you did not want.

Gotcha · never filter on is_dir()

DirEntry::file_type() reports the type of the link, and every entry under /sys/class/hwmon and /sys/class/hidraw is a symlink (foundations, section 07), so .is_dir() is false for all of them and a filter on it returns nothing.

Either use entry.path().is_dir(), which follows the link, or try to read the name file and skip entries where that fails. The reference does the second.

Gotcha · PathBuf, Path, OsString, Cow

Where Go has one string, Rust has a small family. The rules of thumb:

  • PathBuf is to &Path what String is to &str — owned versus borrowed.
  • Build paths with .join(), never format!("{}/{}").
  • Print them with .display(); a path is not directly printable because it is not guaranteed to be UTF-8.
  • entry.file_name() gives an OsString. To compare it as text you want .to_string_lossy(), which returns a Cow<str> — a type that means “borrowed unless I had to allocate”. It shows up in error messages; treat it as a string.

You meet all of this deriving temp1_label from temp1_input. Do it by trimming the suffix off the filename and rejoining, not by .to_str().unwrap().replace(…), which panics on non-UTF-8.

Gotcha · numbering has holes, and iteration is unordered

k10temp has no temp2 (foundations, section 07), so any for i in 1..=n loop is wrong.

read_dir also returns entries in no particular order, so sort if you care. And if you do sort, remember that hwmon10 sorts before hwmon2 lexically (this machine has both).

Gotcha · labels are optional, and that is Option, not Result

A missing label is normal (spd5118, ath12k_hwmon): model it as Option<String>, produced with read_sysfs(&p).ok(), so a RAM sensor you do not care about cannot abort the scan.

Checkpoint

Print what you found with {:?} and diff against the shell:

shell 
for d in /sys/class/hwmon/hwmon*; do echo "$d $(cat $d/name)"; done

Confirm you found k10temp's temp3 and temp4, and that the list is not empty (the symlink trap).

Reference implementation — step 3
src/main.rs 
use std::path::PathBuf;

#[derive(Debug)]
struct Sensor {
    path: PathBuf,
    label: Option<String>, // many drivers expose no label at all
}

/// Every hwmon directory belonging to one driver. Note this does not filter
/// on is_dir(): entries under /sys/class/hwmon are symlinks, so file_type()
/// reports false for all of them. Reading `name` is the real test.
fn hwmon_by_driver(driver: &str) -> Vec<PathBuf> {
    let mut out = Vec::new();
    let Ok(entries) = fs::read_dir("/sys/class/hwmon") else {
        return out;
    };
    for entry in entries.flatten() {
        let dir = entry.path();
        if read_sysfs(&dir.join("name")).is_ok_and(|n| n == driver) {
            out.push(dir);
        }
    }
    out.sort();
    out
}

/// Every temperature sensor in one hwmon directory. Enumerates rather than
/// counting: k10temp exposes temp1, temp3 and temp4 with no temp2.
fn temp_inputs(dir: &Path) -> Vec<Sensor> {
    let mut out = Vec::new();
    let Ok(entries) = fs::read_dir(dir) else {
        return out;
    };
    for entry in entries.flatten() {
        let file_name = entry.file_name();
        let name = file_name.to_string_lossy();
        if !(name.starts_with("temp") && name.ends_with("_input")) {
            continue;
        }
        let label_path = dir.join(format!("{}_label", name.trim_end_matches("_input")));
        out.push(Sensor {
            path: entry.path(),
            label: read_sysfs(&label_path).ok(), // absent is normal
        });
    }
    out.sort_by(|a, b| a.path.cmp(&b.path));
    out
}

4Pick the right GPU

Given two amdgpu instances, choose the discrete card and not the integrated one — and meet iterators.

Among candidate directories for a driver, take the one with the most temperature inputs (the two-amdgpu problem, foundations, section 08), then within it prefer a specific label, and eprintln! the paths you chose at startup; the heuristic can be wrong on another machine.

An iterator chain fits here: .map() transforms each item, .max_by_key() picks the winner, and ? on the resulting Option returns early when there is none.

Gotcha · iterators hand back references

.max_by_key() on a borrowed iterator gives you Option<&T> — a reference — and then you want an owned value to return.

Two escapes: .clone() the thing you need (a PathBuf clone is one small allocation), or use .into_iter() instead of .iter() so the iterator yields owned values. The reference does the second, then clones one path at the end.

Checkpoint

Your finder should land on hwmon6/temp1_input (Tctl) for the CPU and hwmon2/temp1_input (edge) for the GPU — not hwmon3. Load the GPU with something and watch the number move.

Run cargo clippy; it has the most to say about iterator code.

Reference implementation — step 4
src/main.rs 
/// Picks a temperature input for a driver, preferring the first label in
/// `preferred` that exists. Among several instances of the same driver
/// (a discrete GPU and an iGPU both bind amdgpu) the one exposing the most
/// sensors wins: a discrete card reports edge+junction+mem, an iGPU only edge.
fn find_sensor(driver: &str, preferred: &[&str]) -> Option<PathBuf> {
    let best = hwmon_by_driver(driver)
        .into_iter()
        .map(|dir| temp_inputs(&dir))
        .max_by_key(|inputs| inputs.len())?;

    if best.is_empty() {
        return None;
    }
    for want in preferred {
        for s in &best {
            if s.label.as_deref().is_some_and(|l| l.eq_ignore_ascii_case(want)) {
                return Some(s.path.clone());
            }
        }
    }
    Some(best[0].path.clone())
}

fn find_cpu() -> Option<PathBuf> {
    find_sensor("k10temp", &["Tctl"]).or_else(|| find_sensor("coretemp", &["Package id 0"]))
}

fn find_gpu() -> Option<PathBuf> {
    find_sensor("amdgpu", &["edge"])
}

5Find the device and write to it

Locate your /dev/hidrawN by USB ID, then put a number on the panel from your own code.

Discovery is the same directory-scanning shape as step 3 with a different matcher: walk /sys/class/hidraw/*, read each device/uevent, and look for the HID_ID line.

Gotcha · eight hex digits, not four

HID_ID=0003:00002022:00000522: the vendor and product fields are zero-padded to eight digits (foundations, section 10). Build the needle with format!(":{VENDOR_ID:08X}:{PRODUCT_ID:08X}"); the kernel writes uppercase hex too, and the reference upper-cases both sides anyway.

The write half enforces the foundations page's two rules: a 13-byte buffer (0x00, then the packet), sent in one call.

Gotcha · the trait must be imported to be callable

You will write file.write_all(&buf) and get no method named write_all found for struct File, even though File is writable.

write_all comes from the Write trait, and in Rust a trait's methods only exist on a type when the trait is in scope. Add use std::io::Write; at the top.

Gotcha · the file has to be mut

write_all takes &mut self, so let file = File::open(…) followed by file.write_all(…) gives you cannot borrow as mutable.

mut describes the binding, not the file on disk: it says you will call methods that need exclusive access. Say let mut file = ….

(&file).write_all(…) also compiles, because the standard library implements Write for &File as well.

Reach for

OpenOptions::new().write(true).open(path). Not File::create: it adds O_CREAT|O_TRUNC, and if the node is absent it creates a regular file at that path, which every later write succeeds into. Do not add .read(true) “to be safe”: you never read from this device, and a read would block on the IN endpoint.

Reaching for the wrong tool

BufWriter, or writing the header and body in two calls: hidraw maps one write() syscall to one report (foundations, rule two). File::write_all is one syscall for a buffer this size.

Not hidapi or rusb either (foundations, section 02).

Checkpoint

Point the writer at a scratch file first; no root needed:

shell 
$ hexdump -C /tmp/panel.bin
00000000  00 55 aa 01 01 06 04 04  03 04 02 00 18
$ wc -c /tmp/panel.bin
13 /tmp/panel.bin

Exactly 13 bytes. Then the definitive test against the real node:

shell 
$ strace -e trace=write ./target/debug/antec-display
write(3, "\0U\252\1\1\6\4\4\3\4\2\0\30", 13) = 13

One write of 13 bytes per packet. If you get Permission denied, that is the udev rule, not your code — see the foundations page.

Reference implementation — step 5
src/main.rs 
use std::fs::{File, OpenOptions};
use std::io::Write; // without this, .write_all() does not exist on File

const VENDOR_ID: u16 = 0x2022;
const PRODUCT_ID: u16 = 0x0522;

/// Finds the panel by USB ID rather than device number, because
/// /dev/hidrawN is assigned in enumeration order and moves.
fn find_hidraw() -> Option<PathBuf> {
    // HID_ID=0003:00002022:00000522 — eight hex digits per field, not four.
    let needle = format!(":{VENDOR_ID:08X}:{PRODUCT_ID:08X}");

    let mut nodes: Vec<PathBuf> = Vec::new();
    for entry in fs::read_dir("/sys/class/hidraw").ok()?.flatten() {
        let Ok(text) = fs::read_to_string(entry.path().join("device/uevent")) else {
            continue;
        };
        if text.to_uppercase().contains(&needle) {
            nodes.push(Path::new("/dev").join(entry.file_name()));
        }
    }
    nodes.sort();
    nodes.into_iter().next()
}

/// Writes one HID output report. The leading zero is the report-ID byte,
/// which the kernel strips because this descriptor declares no report IDs.
/// One buffer, one write_all: hidraw maps each write() syscall to one report.
fn send(file: &mut File, packet: &[u8; 12]) -> std::io::Result<()> {
    let mut buf = [0u8; 13];
    buf[1..].copy_from_slice(packet);
    file.write_all(&buf)
}

6The loop

Read both sensors, build, send, wait a second, repeat.

Mechanically this is loop { … } and thread::sleep(Duration::from_secs(1)); no async, no channels, no tokio (step 0).

Error policy in a daemon

Inside the loop, errors are not propagated with ?. A sensor read that fails becomes a blank half of the panel and a line on stderr. If you let errors escape the loop, the process exits, systemd restarts it, and you get a restart loop instead of a recovery.

This is also where .unwrap() stops being acceptable: one transient error would panic the daemon. In throwaway code prefer .expect("message") so a panic says which call failed.

Reach for

Option::as_deref() to turn your Option<PathBuf> into an Option<&Path> without giving up ownership. ? also works on Option, not just Result — which makes “no path, so no reading” a single character.

Checkpoint

Watch the panel; the numbers move. Cross-check against watch -n1 sensors. Check top — CPU should be near zero. If it is pegged, your sleep is missing or outside the loop.

Reference implementation — step 6
src/main.rs 
use std::thread;
use std::time::Duration;

/// Reads a sensor, turning any failure into a blanked half-panel.
/// The `?` on an Option returns None early when there is no path at all.
fn read_or_blank(path: Option<&Path>) -> Reading {
    let path = path?;
    match read_temp(path) {
        Ok(c) => Some(c),
        Err(e) => {
            eprintln!("sensor: {e}");
            None
        }
    }
}

fn describe(p: &Option<PathBuf>) -> String {
    match p {
        Some(p) => p.display().to_string(),
        None => "none".to_string(),
    }
}

fn main() -> Result<(), Box<dyn Error>> {
    let cpu = find_cpu();
    let gpu = find_gpu();
    eprintln!("cpu sensor: {}", describe(&cpu));
    eprintln!("gpu sensor: {}", describe(&gpu));
    if cpu.is_none() && gpu.is_none() {
        return Err("no CPU or GPU sensor found under /sys/class/hwmon".into());
    }

    let path = find_hidraw().ok_or("no device 2022:0522 found")?;
    let mut file = OpenOptions::new().write(true).open(&path)?;
    eprintln!("opened {}", path.display());

    loop {
        let packet = build_packet(
            read_or_blank(cpu.as_deref()),
            read_or_blank(gpu.as_deref()),
        );
        if let Err(e) = send(&mut file, &packet) {
            eprintln!("write: {e}"); // step 7 makes this recover
        }
        thread::sleep(Duration::from_secs(1));
    }
}

7Survive a replug

When the device goes away and comes back, reopen it instead of dying or writing to a dead descriptor.

The program now needs to remember something between iterations — whether the device is open — which is what a struct with an impl block is for. Hold an Option<File>: None means “not open”, and dropping the File back to None is how you close it (RAII: there is no defer f.Close()).

Gotcha · re-run discovery, don't reuse the path

After a replug the device may come back as a different /dev/hidrawN, and the remembered path may now be somebody else's keyboard. Re-run discovery.

Checkpoint

Make the device go away — physically unplug the internal header, or do it in software:

shell 
# readlink -f /sys/class/hidraw/hidraw0/device shows the USB device dir: .../usb8/8-7/...
echo 0 | sudo tee /sys/bus/usb/devices/8-7/authorized
sleep 2
echo 1 | sudo tee /sys/bus/usb/devices/8-7/authorized

The program should log the failure, reopen a couple of seconds later, and never exit. If it panics, you still have an .unwrap() in the loop body.

Reference implementation — step 7
src/main.rs 
/// Owns the open device, reopening it after an unplug.
struct Display {
    file: Option<File>,
}

impl Display {
    fn new() -> Self {
        Display { file: None }
    }

    fn ensure_open(&mut self) -> Result<(), Box<dyn Error>> {
        if self.file.is_some() {
            return Ok(());
        }
        // Re-discover rather than reusing a remembered path: the node number
        // can change across a replug.
        let path = find_hidraw().ok_or("no device 2022:0522 found")?;
        let file = OpenOptions::new()
            .write(true)
            .open(&path)
            .map_err(|e| format!("open {}: {e}", path.display()))?;
        eprintln!("opened {}", path.display());
        self.file = Some(file);
        Ok(())
    }

    fn send(&mut self, packet: &[u8; 12]) -> Result<(), Box<dyn Error>> {
        self.ensure_open()?;
        if let Err(e) = send(self.file.as_mut().unwrap(), packet) {
            self.file = None; // dropping the File closes the fd
            return Err(Box::new(e));
        }
        Ok(())
    }
}

8Graceful shutdown

On SIGINT or SIGTERM, blank the panel and exit cleanly instead of leaving a stale number frozen on your case.

Stop the program and the panel keeps its last number; nothing else refreshes it.

Gotcha · std has no signal handling

Rust's standard library has no signal handling, so Ctrl-C takes the default SIGINT disposition and the process dies at once. Drop does not run when a process is killed by a signal, so a destructor cannot blank the panel either.

Three options:

OptionCostVerdict
signal-hookOne dependency (plus libc), safe APIRecommended. Handles both signals, works in the foreground and under systemd
ctrlcOne dependency; needs its termination feature enabled for SIGTERMSimpler API, easy to configure wrongly and then only catch Ctrl-C
systemd ExecStopPost=Zero dependenciesHave systemd run your binary again with a flag such as --blank after the service stops. Does nothing for Ctrl-C in a terminal
Reach for

cargo add signal-hook, then signal_hook::flag::register(SIGTERM, Arc::clone(&stop)), where stop is an Arc<AtomicBool>: the handler runs outside normal control flow, so the flag must be shared (Arc) and safe to touch from two places (AtomicBool). Ordering::Relaxed is enough for one flag.

Gotcha · a one-second sleep is a one-second shutdown

A Ctrl-C that lands mid-sleep waits for the sleep to finish. Sleep in ten 100 ms slices and check the flag between them.

Checkpoint

Foreground, Ctrl-C: the panel shows --.- within about a second and the process exits 0 — check with echo $?. Then kill -TERM the PID and confirm identical behaviour.

Then kill -KILL it. The panel keeps its stale reading — SIGKILL cannot be caught by anything and no destructor runs.

Reference implementation — step 8
Cargo.toml 
[dependencies]
signal-hook = "0.4"
src/main.rs — main, revised 
use std::sync::atomic::{AtomicBool, Ordering};
use std::sync::Arc;

fn main() -> Result<(), Box<dyn Error>> {
    let cpu = find_cpu();
    let gpu = find_gpu();
    eprintln!("cpu sensor: {}", describe(&cpu));
    eprintln!("gpu sensor: {}", describe(&gpu));
    if cpu.is_none() && gpu.is_none() {
        return Err("no CPU or GPU sensor found under /sys/class/hwmon".into());
    }

    // The handler runs outside normal control flow, so the flag must be
    // shared (Arc) and safe to touch concurrently (AtomicBool).
    let stop = Arc::new(AtomicBool::new(false));
    signal_hook::flag::register(signal_hook::consts::SIGTERM, Arc::clone(&stop))?;
    signal_hook::flag::register(signal_hook::consts::SIGINT, Arc::clone(&stop))?;

    let mut display = Display::new();

    while !stop.load(Ordering::Relaxed) {
        let packet = build_packet(
            read_or_blank(cpu.as_deref()),
            read_or_blank(gpu.as_deref()),
        );
        if let Err(e) = display.send(&packet) {
            eprintln!("display: {e}");
        }
        // Sleep in slices so shutdown doesn't wait out a full second.
        for _ in 0..10 {
            if stop.load(Ordering::Relaxed) {
                break;
            }
            thread::sleep(Duration::from_millis(100));
        }
    }

    eprintln!("shutting down, blanking panel");
    let _ = display.send(&build_packet(None, None)); // best effort
    Ok(())
}

9Ship it

A release binary, a udev rule, a systemd unit, and a panel that comes back by itself after a reboot.

shell 
cargo build --release
ls -l target/release/antec-display
ldd target/release/antec-display    # libc and friends, no interpreter

Reuse the repo's udev rule and systemd unit; only ExecStart changes. Note ProtectSystem=strict in the unit: it makes the filesystem read-only except /dev, /proc and /sys, which is all this program needs.

shell 
sudo install -m0755 target/release/antec-display /usr/local/bin/antec-display
sudo cp 70-antec-display.rules /etc/udev/rules.d/
sudo cp antec-display.service /etc/systemd/system/
sudo sed -i 's|^ExecStart=.*|ExecStart=/usr/local/bin/antec-display|' \
  /etc/systemd/system/antec-display.service
sudo udevadm control --reload-rules && sudo udevadm trigger --subsystem-match=hidraw
sudo systemctl daemon-reload
sudo systemctl enable --now antec-display
You do not need a logging crate

journald captures stdout and stderr with timestamps, so eprintln! is sufficient; no log, env_logger or tracing, and no clap or serde either. The project has one dependency.

Optional

std::env::args() for a few flags — --once, --dry-run to print hex instead of writing, --device to override discovery — and std::env::var for ANTEC_CPU_SENSOR-style overrides, which returns a Result you can .ok() into an Option.

anyhow's .context(…) attaches the file path to an error without a map_err(|e| format!(…)) each time; add it if those get tedious.

Checkpoint

systemctl status antec-display is clean, and journalctl -u antec-display -f shows your two startup lines naming the chosen sensors.

Restart twice. systemctl stop and confirm the panel blanks rather than freezing, which is step 8 working through systemd's SIGTERM.

Then reboot and confirm it still finds the right hidraw node and hwmon directories.
